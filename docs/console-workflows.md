# 控制台操作与恢复语义

启动和账号配置见 [本地启动指南](local-start.md)。控制台提供 API 工作台、运行记录、手动 Python 诊断、Trace、Evaluation 和 Benchmark 阅读入口。

## 用例编辑与执行

在 API 工作台选择项目与接口，通过 Java 或 Python AgentLab 生成用例。修改 DSL 后点击“Java 校验”，通过后才能执行。每次修改使上一次校验失效；历史恢复的 DSL 也需重新校验。校验覆盖共享 Schema、项目权限和目标绑定。切换语言应保留正在编辑的内容。

Java 校验入口为 `POST /api/v1/projects/{projectId}/openapi/apis/{apiId}/testcases:validate`。

DSL 草稿按账号、项目、文档、接口、策略和生成运行时保存在当前标签页的 sessionStorage；
页面切换、刷新后恢复最近选择和草稿，恢复后仍须重新通过 Java 校验。退出登录会清除草稿。
浏览器存储不可用时保留内存副本，并提示刷新前复制。提交执行后切换项目或接口，旧请求的
响应不会写入新页面；服务器已经接受的运行仍可从所属项目的运行记录查找。

## 取消与重跑

运行控制接口前缀为 `/api/v1/projects/{projectId}/test-runs/{runId}`：

- `GET /controls` 读取可执行操作；读取失败可刷新，不重新提交动作。
- `POST /cancel` 请求取消所属批次中尚未开始的任务；已开始任务允许完成。
- `POST /rerun` 从持久化快照创建新 batch/run，保留来源链接和原始记录。

接口随既有 RabbitMQ execution 配置启用，并沿用认证和项目权限。动作提交成功但刷新失败时，保留返回的新 runId，先读取状态再决定下一步。

消息投递失败时，批次与尚未开始的成员运行一起结束为失败；取消批次时尚未开始的成员结束为取消。
已开始和已结束的成员状态不会被覆盖。运行列表每次读取 100 条，可点击“加载更早的运行”继续读取；
搜索与状态筛选作用于已加载记录，刷新运行状态不会丢弃已加载的旧页。

## 诊断恢复

工作台 URL 保存项目与 runId。页面先读取服务端历史，恢复运行中或待审批记录；历史读取失败时先重试读取，避免重复启动。待审批任务通过既有审批入口继续。

各页面均有 URL 入口，支持刷新和浏览器前进、后退；接口、运行、诊断报告和 Trace 的选择也保存在 URL 中。
跨项目历史导航会重新检查可访问项目；不可访问项目的详情标识不会带入当前项目。

后端按项目和来源运行编号使用操作系统文件锁，覆盖持久化与整个异步工作流。启动会复用待审批或最新已完成结果；最新失败、拒绝或中断记录允许重新诊断。HTTP 409 `DIAGNOSIS_ALREADY_RUNNING` 使控制台刷新已有诊断。

服务崩溃后锁由操作系统释放。后续经授权的历史/详情读取或启动会将没有工作进程持锁的 RUNNING 记录标记为 FAILED，原因是 `DIAGNOSIS_INTERRUPTED`。保留历史和审批 checkpoint，不自动重放可能已执行的工具调用。

这一机制适用于共享本地 SQLite 的单机部署，不是跨主机分布式锁；运行期间不能删除锁文件。自动诊断触发及 Java 浏览器诊断尚未实现。

## 报告与结果

运行详情与诊断报告支持 Markdown、JSON 导出，保留来源、失败信息、证据和空值。运行导出包含脱敏 HTTP 快照，诊断导出不包含审批工具参数。快照来源、截断和旧记录兼容见 [HTTP 快照说明](http-exchange-snapshots.md)。

语言切换翻译 UI，不改写 DSL、接口原始内容、模型正文和历史证据。Evaluation 展示运行评估；Benchmark 只读取 [已发布的正式结果](benchmark-publication.md)，不会启动模型调用或重跑评测。

Python HTTP 客户端复用进程内只读 TLS 配置以减少重复加载证书的开销，仍校验证书和主机名；不缓存令牌、授权结果或接口响应，每次读取仍须校验项目权限。

## 验证入口与限制

前端专项检查见 `apiops-console/package.json` 的 `test:editor`、`test:routes`、`test:diagnosis`、`test:console-execution`、`test:i18n` 和 `test:reports`。Java 运行控制、校验、快照测试及 Python API、contracts、services 测试覆盖相应边界。

浏览器验证需另外确认下载文件落盘、真实待审批任务提交和取消中的批次状态；构建或单元测试不代替这些检查。取消测试使用正常目标 `18080`；`18081` 是预期返回故障的靶场，不能把其 HTTP 500 归因于取消逻辑。
