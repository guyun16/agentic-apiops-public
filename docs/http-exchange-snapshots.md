# 请求与响应快照

Java Runner 在构建实际 `HttpRequest` 并执行 transport 后生成快照；没有响应的连接失败、超时也保留已构建请求。构建请求失败时不生成快照。请求正文取自构建器使用的同一 `RequestSpec.body`，不重新订阅 body publisher，不修改传输、断言或变量解析。

快照写入 `step_exchange_snapshot`，主键和外键均为 `step_result_id`，同一事务与执行结果一起保存。报告通过已有项目权限查询返回每步可选的 `httpExchange`。旧步骤没有快照时返回 `null`，不会从接口元数据推测请求或回填历史数据。部署时执行 `apiops-runner/src/main/resources/db/runner-schema.sql` 中新增的 `CREATE TABLE IF NOT EXISTS`；无需修改旧表或历史记录。

控制台运行详情的请求、响应页签显示快照；合并展示的重复步骤可展开每一次实际执行。旧记录保持“未记录快照”的提示。

脱敏采取保守策略：

- JSON 字符串值全部隐藏，敏感字段的整个值隐藏，包括密码、token、cookie、session、API key、联系方式等。保留 JSON 结构、非敏感数值和布尔值。
- 查询参数值、路径参数值、敏感路径段和 URL 用户凭据隐藏。仅保留合法 MIME 类型和 Content-Length 头值，其余请求／响应头值隐藏。
- 非 JSON、无效 JSON、二进制正文不展示；不会先截断原文再尝试脱敏。输入超过 65,536 个字符时直接省略，脱敏后正文最多 8,192 个字符。头部最多 32 项，URL 最多 2,048 个字符；嵌套深度超过 16 时省略，均保留截断标识。
- 原始响应仅用于原有运行与断言处理；新增表只保存脱敏快照。快照生成失败时降级为不可用，不改变执行结果。

快照适合确认请求目标、状态码、JSON 结构和数值，不是可复用的完整原始报文。代码块只以文本渲染，不解释正文中的 HTML。

自动化验证覆盖真实构建请求／响应来源、凭据与任意字符串隐藏、原对象不变、无响应、JSON null、无效或非 JSON 正文、大小限制、旧报告兼容以及损坏可选快照回退。MySQL Testcontainers 测试覆盖快照事务持久化与读回和项目隔离。
